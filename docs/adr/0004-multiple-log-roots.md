# 複数のログルートをスキャン対象にできるようにする

Claude Code は `.claude` ディレクトリ全体の場所を `CLAUDE_CONFIG_DIR` 環境変数で変更できる(プロセス単位で1値のみ、同時に複数は持てない)。マシンやシェル環境ごとに異なる `CLAUDE_CONFIG_DIR` を使っているユーザーは、実行時点では1つしか値を持てなくても、手元には複数の `.claude/projects/` ディレクトリ(ログルート)が存在しうる。これらすべてを合算してコストを把握したいという要望に応え、`config.toml` の `roots` に追加のログルート(絶対パス)を並べられるようにする。

- **デフォルトルートの解決**: cc-cost 自身も `CLAUDE_CONFIG_DIR` を尊重し、未設定なら `$HOME/.claude/projects`、設定されていれば `$CLAUDE_CONFIG_DIR/projects` をデフォルトルートとする。`roots` で指定した追加ルートは、このデフォルトルートに**加算**される(置き換えではない)。既存ユーザーの挙動は `roots` 未設定なら変わらない。
- **一部ルートの欠落**: 存在しないルートは警告を出してスキップし、残りのルートで集計を続行する。全ルートが存在しない場合のみエラーで終了する(1ルートしか無かった従来の挙動を拡張したもの)。
- **プロジェクト名の衝突**: 異なるログルートに同名のプロジェクトディレクトリ(例: 同じパスを異なる環境で開いた場合)が存在しても、常に別プロジェクトとして扱い、usageを合算しない。ただし `project_groups` の正規表現がルートをまたいで同じディレクトリ名にマッチした場合は、既存の仕様通りその1グループへ合算する(グルーピングは元々複数プロジェクトを束ねる表示上の機能であり、ユーザーが意図してパターンを書いている)。
- **表示上の衝突回避**: どのパターンにもマッチせずディレクトリ名がそのままフォールバック表示名になるケースでのみ、同名ディレクトリがルートをまたいで複数存在する場合に、表示名にルートのパスを付与して区別できるようにする(例: `/repo/path [/home/dev/.claude/projects]`)。

ハッシュ化や短縮エイリアスなどの複雑な識別方式は導入しない。ルートのパスをそのまま表示すれば十分に区別でき、個人利用のコスト把握ツールとしては可読性を優先した。
